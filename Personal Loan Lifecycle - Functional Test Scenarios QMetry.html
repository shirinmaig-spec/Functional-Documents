Format: One row per test case, mapped to QMetry's standard test-case import fields (Summary, Precondition, Priority, Component, Labels, Step Test Data, Step Action, Step Expected Result).
Priority rule: Critical = security findings allowing unauthenticated state changes or maker/checker bypass · High = confirmed defects/gaps that should block release · Medium = standard positive/negative regression cases · Low = boundary/investigative cases needing manual or DB verification.
Source: Direct conversion of the 7 field-level test case documents (Creation, Verification, Approval, Disbursement, Repayment/Collection, Pre-Closure/Restructuring/NPA, Reports/Masters) — no new claims introduced; every row traces to the same code evidence as the underlying functional documentation.
Import note: Cases labeled Defect or Gap represent currently-unblocked scenarios the system does not prevent today. When scripting these as test executions, "Pass" should mean the vulnerable behavior has been fixed, not that today's behavior is correct — mark them "Expected to Fail until remediated" so a test run isn't misread. Cases labeled Unknown require direct execution against a live environment to resolve — they are not assumed pass or fail.
